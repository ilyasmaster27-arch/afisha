# Campus Pulse — сценарии проверки

Перед тестом выполните `supabase/schema.sql`, настройте `.env.local` и создайте два подтверждённых аккаунта: A и B.

| № | Шаги | Ожидаемый результат |
|---|---|---|
| T01 | Открыть сайт без входа | Каталог загружается, кнопки создания и участия требуют вход |
| T02 | Аккаунтом A создать событие с валидными полями | Событие появляется в каталоге и разделе «Мои события» |
| T03 | В форме указать короткое название, описание или прошедшую дату | Под соответствующим полем появляется ошибка, запрос не отправляется |
| T04 | Аккаунтом B открыть событие A и нажать «Участвовать» | Появляется состояние «Вы участвуете», событие видно в «Мои записи» |
| T05 | Аккаунтом B повторно отправить INSERT с теми же `event_id`, `user_id` | База отклоняет дубликат первичным ключом |
| T06 | Аккаунтом B отправить UPDATE или DELETE для события A через Supabase client/DevTools | RLS не изменяет и не удаляет строку A |
| T07 | Аккаунтом B запросить строки `event_members` аккаунта A | RLS не возвращает чужие записи |
| T08 | Аккаунтом B отменить участие | Собственная запись удаляется, событие остаётся |
| T09 | Аккаунтом A изменить своё событие | Новые данные появляются в каталоге после запроса к БД |
| T10 | Аккаунтом A удалить своё событие | Событие и связанные записи участников удаляются |
| T11 | Открыть сайт на ширине 375 px | Одна колонка, фильтры прокручиваются внутри панели, нет горизонтальной прокрутки страницы |
| T12 | Отключить сеть и обновить каталог | Видно сообщение об ошибке и кнопку повтора, интерфейс не зависает |
| T13 | Собрать `npm run build` | Команда завершается без ошибок, файлы появляются в `dist/` |
| T14 | Открыть GitHub Pages по URL репозитория | Стили и JS загружаются, вход и запросы Supabase работают |
